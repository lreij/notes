agent skill是anthropic的阴谋吗？skill是高质量的workflow文本数据，可以很容易被训练到大语言模型里面。anthropic公司通过
发明skill这个概念，号召所有人和公司编写skill，是否是以达到获得高质量workflow训练数据的目的？虽然没有证据，但是毕竟skill
把“隐性知识”转化成了“机器可消费的程序性知识”，可以把 Skill 描述成 reusable procedural knowledge，而现在已经有很多
开源的skill，大模型公司很容易获得。

结论先说：作为“阴谋”，这个假说的动机部分不成立，但你指出的现象部分是真的——技能确实把隐性知识变成了机器可消费的程序性知识，
而这件事的真正价值不在预训练语料，在别处。

先算一下量级。一个 skill 文件大约 2–5 KB，约 1000 token。假设公开世界最终存在 10 万个 skill，总量约 10^8
token。前沿模型的预训练语料在 10^13 token 量级。也就是说全世界所有开源 skill
加起来，占语料的十万分之一。就算按稀有高质量数据上采样 100 倍，也仍然是噪声。相比之下，Claude Code 一天的真实使用产生的
tool call 轨迹、报错、修正、重试，token 量很可能就超过整个公开 skill 语料库。（这些是数量级估算，不是官方数字。）

更关键的是数据质量的方向。训练 agent 行为最值钱的不是静态 SOP 文本，而是 轨迹 +
结果：模型做了什么、失败在哪、人怎么纠正、最终是否成功。skill
只是轨迹的先验说明书，是最廉价的那一层。如果目的真是收割程序性知识，产品本身就是管道，不需要发明一个格式来绕路。

还有一个更根本的反转：skill
是训练的替代品，不是训练的原料。如果模型能在运行时读到工作流，你就不必把这套流程烧进权重。把领域流程外置到文件里，恰恰降低
了针对每个细分领域做后训练的必要性。这是它作为工程手段的第一动因——上下文窗口经济学：你塞不进所有东西，所以需要一个
description 索引 + 按需加载。这个解释不需要任何阴谋成分就能完整说明 skill 为什么长这个样子。

另外，公开的 skill 对 Anthropic 没有排他性。放在 GitHub 上的东西，OpenAI、Google、Meta
抓取成本一样低。设计一个让竞争对手等额受益的数据收割计划，策略上是自伤。

真实的动机大概率是标准制定，MCP
就是模板：公开规范、放弃控制权、成为默认基础设施层。这条路的回报（生态锁定、工具链默认依赖、招聘和心智占位）远高于几十亿
token
的边际语料。基础率也支持这个解释——公司开源一个格式以成为标准，先例极多（Docker、Kubernetes、LSP、OpenAPI、MCP）；公司发明开
发者格式主要为了刷预训练数据，我想不出清晰先例。

怎么把它变成可检验的

如果“收割语料”是真动机，你应该观察到：条款里针对 skill 文件单独主张训练权利；出现一个由 Anthropic 拥有的中心化
registry，且上传或遥测是必需的；不鼓励纯本地 skill；推动统一的宽松许可。

实际观察到的是：skill 是磁盘上的本地文件，离线可用，规范公开，而且可移植——同一批文件被人拿去喂别家的 agent
CLI。这对收割假说是弱证据，对标准制定假说是强证据。

会让你的假说加分的信号：出现强制提交或默认开启遥测的技能市场；或者条款开始区分“技能内容”与“会话内容”的授权范围。这条值得盯
着。

你的直觉里对的部分

真正该关心的不是公开 skill，是私有 skill。企业把内部 SOP、风控流程、客户处理规则写成 skill 放进 agent
的上下文路径，这是把最核心的隐性知识主动送到供应商的输入管道里。这不是预训练问题，是保密与条款问题，边界取决于你用的是哪个
档位的服务。我这次没有去核对 Anthropic 当前的条款细节（消费者档与商业 API 档的训练与留存策略不同，且 2025
年有过变更），需要的话我可以查一下当前版本再给你准确表述。

还有一层二阶效应值得记下来：定义技能格式的人，同时也在定义“什么算一个好流程”——多长、多细、怎么切分、成功标准怎么写。这是对
工作分解方式的软性影响力，比数据更持久，也比数据更难察觉。

实务上的做法很朴素：专有流程放私有仓库，skill 文件里不写密钥和客户数据，确认你所在服务档位的留存与训练策略，并且记住 skill
是纯文本、可移植，锁定风险本身很低。
